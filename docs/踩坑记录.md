# 踩坑记录：STM32F103 + FreeRTOS 开发常见问题

## 1. printf 无输出的问题

### 现象
任务中调用 `printf()`，串口没有任何输出，但 LED 闪烁和按键功能正常。

### 原因
CubeMX 生成的 `Core/Src/syscalls.c` **没有被编译进项目**（不在 Makefile 的 C_SOURCES 中）。

printf 的调用链路：
```
printf → _write → __io_putchar → HAL_UART_Transmit
```

由于 `syscalls.c` 未被编译，链接器使用了 newlib 内置的弱符号 `_write`，其默认实现为空（静默丢弃所有输出）。即使在 `usart.c` 中定义了 `__io_putchar`，`_write` 也不会去调用它。

### 解决方案
在 `usart.c` 中直接提供 `_write` 的强定义，覆盖 newlib 的弱符号：

```c
int _write(int file, char *ptr, int len)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)ptr, len, HAL_MAX_DELAY);
    return len;
}
```

同样地，`_read` 也需要强定义才能使 `scanf`/`gets` 工作：

```c
int _read(int file, char *ptr, int len)
{
    for (int i = 0; i < len; i++)
        ptr[i] = __io_getchar();
    return len;
}
```

### 补充说明
- `__io_putchar`/`__io_getchar` 是 CubeMX 的 `syscalls.c` 定义的机制（`_write` 逐字节调用 `__io_putchar`）
- 直接定义 `_write` 可整批发送，效率更高
- 如果 `syscalls.c` 被加入 Makefile（`C_SOURCES += Core/Src/syscalls.c`），原方案也可以工作

## 2. 任务函数漏写闭合大括号

### 现象
修改 `StartDefaultTask` 后，按键和 printf 同时失效，系统只有 LED 在闪。

### 原因
编辑 `freertos.c` 时替换了函数体内容，但**删掉了 `for(;;)` 循环和函数末尾的闭合大括号 `}`**。

导致 `StartLed1Task` 和 `StartKeyTask` 的代码被嵌套在 `StartDefaultTask` 内部，三个函数变成了一团乱码，程序结构完全破坏。

错误的结构示意：
```c
void StartDefaultTask(void *argument)
{
    for (;;)
    {
        // ...
    // ← 缺少 } 结束for循环
    // ← 缺少 } 结束函数

    void StartLed1Task(void *argument)  // ← 意外嵌套在函数内部！
    {
```

### 解决方案
补回两个缺失的 `}`：

```c
void StartDefaultTask(void *argument)
{
    for (;;)
    {
        HAL_GPIO_TogglePin(LED0_GPIO_Port, LED0_Pin);
        osDelay(200);
    }       // ← for循环闭合
}           // ← 函数闭合
```

### 教训
- 使用 Edit 工具替换大段代码时，注意检查替换内容是否完整包含所有闭合符号
- 修改后先编译确认无语法错误，再烧录测试

## 3. FreeRTOS 任务栈大小与 printf

### 现象
`defaultTask` 任务栈设为 `128 * 4`（512 字节）时按键工作但 printf 无效；
栈增大到 `512 * 4`（2048 字节）后按键也失效了。

### 原因
- 栈 512 字节时：printf 内部缓冲导致栈溢出，表现为 printf 无输出
- 栈 2048 字节时：无意中引入的大括号缺失问题（见上一条），导致所有任务异常
- 真正的 printf 问题（`_write` 未定义）才是根源，与栈大小无关

### 解决方案
- `printf` 之前调用 `setvbuf(stdout, NULL, _IONBF, 0)` 关闭缓冲
- 使用 printf 的任务建议栈 ≥ 1024 字节（`256 * 4`）
- 最重要的是提供 `_write` 实现（见问题 1）

---

## 4. 通用建议

| 问题 | 排查方法 |
|------|----------|
| printf 无输出 | 检查 `_write` 是否有强定义 |
| 功能异常 | 检查代码结构（括号匹配） |
| 部分任务不工作 | 检查栈大小是否足够 |
| 编译正常但运行异常 | 检查 CubeMX 再生是否覆盖了非 USER CODE 区域的代码 |

所有修改应在 CubeMX 的 `/* USER CODE BEGIN */` 和 `/* USER CODE END */` 注释块内进行，避免代码再生时被覆盖。
